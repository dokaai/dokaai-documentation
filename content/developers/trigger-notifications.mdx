---
title: "Trigger notifications from an application"
description: "Trigger an already configured handler from a server-side application."
---

Before integrating, [create client credentials](/account/api-credentials) and obtain the project and handler identifiers. The handler needs [configured channels/templates](/build/templates) and a [recipient source](/build/recipients). A teammate can prepare this configuration in the dashboard.

## Prepare the integration

1. Read the existing [Authentication reference](/api-reference/authentication) and store the client key/secret in backend secret storage.
2. Open [Trigger Notification Handler](/api-reference/notification-handlers/trigger-notification-handler) for the canonical URL, request body and response contract.
3. Supply the selected handler's recipient and template data according to that contract. Keep shared template values separate from per-recipient data and review channel-specific definitions.
4. Start with a controlled recipient and an explicit test-mode choice. If using the dashboard's generated request as a starting point, review its target, mode and data before executing it.
5. Submit the request from your server and retain the response/event identifiers needed to investigate the result.

Do not send client credentials from a browser or substitute dashboard session cookies for public API authentication.

## Inspect and handle the result

Treat request acceptance separately from delivery. Inspect the corresponding [handler event](/operations/events) and handle errors returned by the API. Do not automatically replay a failed or timed-out send without checking its outcome; this guide does not establish an idempotency or retry contract.

Use [Authentication diagnostics](/troubleshooting/authentication) for credentials and [Delivery investigation](/troubleshooting/delivery) for execution results.
