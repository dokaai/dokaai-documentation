Dokaai brings notification handlers, channel templates, customer audiences and preferences into a shared dashboard. Start with the task you want to complete.

## New to Dokaai?

First, [sign in or accept your team invitation](/account/access). If you can already access the intended organization and project, continue with the concepts and setup below.

Start with [Core concepts](/concepts). An organization is your account, a project is where you configure notification work, a product space represents the app/brand, and a service is the Dokaai product you enable. A handler holds reusable notification configuration; an event records one run.

For example, a shop can configure an order-confirmation handler once, then trigger it with the details of each new order. Templates define the content, recipients identify who to target, and preferences/send policy describe communication choices and configured send rules.

Follow this setup sequence: [account and project setup](/account/setup), including service enablement and product-space association → [customer pool](/customers/pools) → [handler](/build/handlers). Revisit the relevant section as you complete each dashboard step.

## Send your first notification

Follow the [Quickstart](/quickstart) to configure a handler, send a test notification to a recipient you control and inspect its handler event. The walkthrough links to each configuration guide so you can continue without repeating setup.

## Connect providers and use the API

Use the existing [Integration directory](/integration) for provider discovery and setup. A handler's channel configuration selects the provider integration it uses.

The [API Reference](/api-reference) owns request and response contracts. For application sends, start with [authentication](/api-reference/authentication) and the [Trigger Notification Handler operation](/api-reference/notification-handlers/trigger-notification-handler).
