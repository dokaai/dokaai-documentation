An organization is the company or team account you select in Dokaai. It provides the context for projects and organization-level configuration.

## Organization and project areas

| Context | Dashboard areas |
| --- | --- |
| Organization | Org Services, Org Members, Projects, Billing, API Keys, Channel Integrations, Send Policy and Customer Auth Keys |
| Project | Project Members, Customers, Preference Groups, Notification Handler and Job Status |

Choose the organization first, then the project whose customers and handlers you want to manage. Check both selections when something you expect to see is missing.

## Use the right configuration context

Provider integrations and API credentials are managed from the organization area. Handler configuration, audiences and notification events belong to the project work you are doing. An organization membership and a project role are separate access-management concerns; review the roles available for the intended context rather than assuming the same access everywhere.

[Set up an organization and project](/account/setup), then [manage members and roles](/account/members-and-roles) or begin [configuring a handler](/build/handlers).

## Example account setup

Acme selects its organization, subscribes to the notification service and creates an Acme Shop project. The project is associated with the Acme Shop product space and enables the subscribed service. Team members can then configure its customer pool and handlers. An organization subscription, a project, a product-space association and a provider connection are distinct parts of that setup.

Continue below for projects, or read about [Product spaces](/concepts/product-spaces) and [Services](/concepts/services).

## Projects

A project is where your team configures and operates a set of notifications. Select a project within your organization to work with its customers, preference groups, handlers and background jobs.

### Organization, project and product space

| Object | What it answers | Example |
| --- | --- | --- |
| Organization | Which company or team owns the account? | Acme |
| Project | Which notification configuration and customer work are you managing? | Acme Shop notifications |
| Product space | Which app or brand does this project relate to? | Acme Shop |
| Service | Which Dokaai product is subscribed to and enabled here? | The notification service |

A project is associated with a product space. Multiple projects can use the same product space, so choosing a project and choosing a product space are separate decisions. See [Product spaces](/concepts/product-spaces).

### What you manage in a project

The project navigation contains Project Dashboard, Project Members, Customers, Preference Groups, Notification Handler and Job Status. Channels and templates are configured inside a handler. Organization-level provider integrations and API credentials are managed from the organization area.

[Create or select a project](/account/setup), [enable its service](/account/setup#services), then configure its [handlers](/build/handlers). Check the project selection when a handler or customer pool seems to be missing.

### What does workspace mean?

Older pages and customer-authentication fields use the word workspace. The dashboard's account structure uses organizations and projects; this guide does not introduce another workspace object for you to create. Customer authentication has a specific workspace identifier supplied with signing configuration. Use that value and the [Authentication reference](/api-reference/authentication), rather than assuming an organization ID or project ID can replace it.
