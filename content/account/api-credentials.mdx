---
title: "Manage API credentials"
description: "Create and store client credentials for server-to-server API requests."
---

Client API credentials are used by your backend when calling Dokaai APIs. Dashboard session access and customer signing keys serve different purposes.

## Create credentials

1. Select the organization and open **API Keys**.
2. Choose **Create API Key** and enter a name identifying the application or purpose.
3. Submit the form and review the success dialog.
4. Copy or download the API key and API secret, and store them in your backend's secret storage before closing the dialog. The dialog warns that the secret will not be shown again.

Do not put the client secret in browser code, mobile bundles or source control. Keep it out of request logs and screenshots shared for support.

## Use the credentials

Use the existing [Authentication reference](/api-reference/authentication) for the canonical request-header contract. Do not substitute a dashboard session cookie or a customer JWT for the client credentials expected by the operation.

Once a handler is configured, follow [Trigger notifications from an application](/developers/trigger-notifications). If authentication fails, use [Authentication diagnostics](/troubleshooting/authentication) and check the credentials and organization/project context without exposing the secret.

## Delete or replace credentials

Review the key list's name, active/inactive state and identifying details before changing a credential. For deletion, use the key's delete action and type the expected key name in the confirmation. Check that the operation succeeded and review the resulting list.

For an application replacement, create and securely capture the new pair, update the backend that uses it, and verify that application's requests before deleting the old credential. Coordinate the change with every consumer; this is a replacement procedure, not a documented automatic rotation or overlap guarantee. Do not assume that a secret can be retrieved again from a list/detail view.
