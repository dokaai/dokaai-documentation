Prepare the organization and project before configuring notifications. If you have not signed in or joined your team, start with [Get access to Dokaai](/account/access). You need permission for each setup action; a teammate can complete the steps your role does not allow.

## Organization and project

1. Select an existing [organization](/concepts/organization), or create the company/team account with a name and description.
2. Open **Projects** in that organization and create or select the intended project. A project is the context for its handlers, customer work, members and jobs.
3. On **Project Dashboard**, review the setup actions for services, product space and members. The following sections explain those actions.

## Services

Before configuring notifications, check both the organization subscription and the project's service enablement. You need the corresponding account permissions. [Services](/concepts/services) explains the difference.

### Review the organization subscription

1. Select the intended organization and open **Org Services**.
2. Find the notification service card and inspect its subscription/billing state.
3. If it offers a subscription action, open it and review the confirmation and billing terms shown for your account before confirming.
4. Wait for the result, then reload the service list to verify the subscription state.

A card marked **Coming soon** is informational. Do not assume its product is available because its name or logo is present.

### Enable the service in your project

1. Open **Project Dashboard** for the intended project.
2. In project setup, use **Open org services** if an organization subscription is still needed.
3. Once the organization subscribes, use the offered **Enable** action and confirm the project.
4. Check that setup reports the service as enabled. Complete the product-space and member steps as appropriate for the project.

The project service view also displays enablement and organization/project billing-paused states. If access remains unavailable after enabling, check those states and your project role.

### Pause or resume billing

The organization service card offers **Pause billing** or **Resume billing** where available. Review the confirmation's access and billing implications before changing a live account. Verify the result in the service card and [Billing and usage](/operations/billing-and-usage); do not interpret billing pause as a handler-level stop switch.

Then complete product-space association below and continue with [Quickstart](/quickstart).

## Product spaces

Use a [product space](/concepts/product-spaces) for the app or brand your project belongs to. Start in the correct organization's **Project Dashboard**.

### Create or associate a product space

1. Open the product-space setup action or the existing product-space association controls on the project dashboard.
2. Search the organization's available spaces. If the intended app/brand already exists, select that space rather than creating a duplicate.
3. To create a new space, use the create action, enter its name and optional description, and save it.
4. Select the intended space and choose **Associate**.
5. Recheck the project dashboard's product-space name after the operation succeeds.

The name describes the app/brand; the space's code and ID are separate identifiers. Multiple projects may use the same product space.

### Switch an existing association

The same controls offer **Switch Product Space** when the project already has an association. The confirmation asks for the current product-space name and warns that the change may invalidate customer preferences in linked handlers.

Before confirming, identify the affected handlers and any customer signing/integration configuration. After the switch, review the handlers and configure their preference associations for the new product space. Coordinate customer-facing changes with the application owner. The UI warning should not be treated as a complete migration contract for every deployment.

See [Handler preferences](/preferences/groups-and-topics#handler-preferences), [Customer signing keys](/developers/customer-authentication#signing-keys) and [Customer authentication](/developers/customer-authentication).

## Team access

Use **Org Members** and **Project Members** for their respective scopes. Add or invite the people who will manage this project, choosing the roles offered for that context. See [Members and roles](/account/members-and-roles).

## Customer pool and provider

Select or create a [customer pool](/customers/pools) available to the project. Handler creation requires a pool selection, even when recipient contacts will come from a trigger payload. List/cohort membership is needed only for the recipient source you choose.

Configure the intended provider from the organization's **Channel Integrations** area and existing [Integration directory](/integration). Continue with [Quickstart](/quickstart) or [Configure notification handlers](/build/handlers).

Create [API credentials](/account/api-credentials) when an application backend will trigger notifications. Customer-facing inbox/preference integration also needs [Customer authentication](/developers/customer-authentication).
