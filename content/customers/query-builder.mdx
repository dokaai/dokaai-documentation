---
title: "Build audience queries"
description: "Create typed rules, inspect samples, save a cohort, or populate a target list from a query."
---

An audience query selects customer records by their attributes. Use the query builder from a [cohort](/customers/target-lists#cohorts) or a target list's query flow. Start with the intended [customer pool](/customers/pools), the relevant attributes, and access to manage its audience work.

## Build rules and groups

Choose a field, an operator and the value to compare. Combine rules with **AND** when every condition must match, or **OR** when any condition can match. Use nested groups to make that grouping explicit.

For example, if your pool has `account_tier` and `order_count` fields, you could select customers whose account tier equals `premium` AND whose order count is greater than `0`. Choose your actual pool fields and their correct types; the example does not create those attributes for you.

| Field type | Examples of offered comparisons |
| --- | --- |
| String | Equal/not equal, contains, begins/ends with, any/none of |
| Number, date or date/time | Equality, ordering, between/not between, any/none of |
| Boolean | Equal/not equal |
| Array | Any/none of |
| JSON | No comparison operators in the current field-type mapping |

Some fields, including timezone and pincode, have more restricted operator choices. Use the operators offered for the selected field. Resolve invalid or incomplete rules before saving or running.

## Load a sample

Load sample data and inspect representative records before using the query. The current sample view displays up to 20 returned rows. Those rows are not a complete audience or proof of the total match count. If you edit the query after sampling, reload the sample: the earlier sample can be stale.

## Save a cohort query

In the cohort query view, save the validated definition and reopen it to check the persisted rules. Saving a cohort definition is different from adding its matching customers to an explicit target list. Do not assume a refresh schedule or automatic list synchronization from the presence of a saved query.

## Run a query to populate a target list

In the target list's query flow, review the destination list and use the run action. The confirmation requires its name and offers:

- **Run query:** execute the query directly and create a background job without saving it as a cohort.
- **Save and run query:** first save the definition as a named cohort, then execute it for the target list.

Review the returned job reference and use **View job detail** or [Background jobs](/operations/jobs) to inspect completion. Recheck the target list's membership after processing. A created job is not confirmation that every matching customer was added. If a save succeeded but execution failed, inspect both outcomes before retrying so you do not create unnecessary duplicate definitions or jobs.

## When editing is unavailable

Read-only pool access can allow inspecting a query while disabling save/run actions; custom-attribute editing has separate permissions. See [Shared-pool permissions](/customers/pools#shared-pools-and-access) and [Audience diagnostics](/troubleshooting/audiences).
