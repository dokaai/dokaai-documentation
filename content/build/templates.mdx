Before authoring a template, [configure its handler channel](/build/channels). Choose the channel whose content you want to manage.

## Create and review content

1. Open the handler's template area for the selected channel.
2. Create or select a template and enter a recognizable name.
3. Edit the content using the controls available for that channel. For email, see [Email design tools](/build/templates#email-design-tools).
4. Review any variable references and the data they require. See [Template variables and personalization](/build/variables).
5. Save the template and reopen it to check its content and settings.

Where an external/provider template is used, follow the existing provider guide in [Integration](/integration) for the provider's requirements. Creating content in Dokaai does not by itself establish provider approval.

## Match content to the channel

| Channel | Content to review |
| --- | --- |
| Email | Subject, email document and any configured attachments/images |
| SMS | Message text and its variable references |
| Push | Title/body and any configured image, action or other push fields |
| WhatsApp | Template header/body/footer, buttons, variable examples and [approval state](/build/templates#whatsapp-template-approval) |
| In App | Notification title/body and any configured actions or content sections |

Use the controls and validations offered for the selected channel/provider. A template for one channel does not automatically define the content needed by another channel.

## Publish and test

Use the template's publish action when the content is ready. Template publication and handler publishing state are separate; review both before triggering.

Then [test a send](/build/test-and-send) and inspect the resulting handler event. If references are invalid or values are missing, use [Template diagnostics](/troubleshooting/templates).

For API automation, see [Get Channel Template](/api-reference/notification-handlers/get-channel-template-by-id) and the handler/channel operations in the existing reference.

## Email design tools

Open an email [channel template](/build/templates) to edit its subject and document content. Keep content design, variable data and publishing as separate review steps.

### Design and review an email

1. Edit the subject and email document with the available editor controls.
2. Use the variable suggestions for the attributes and send-time values that the message needs.
3. Review the preview and any diagnostics before saving.
4. Save the template, then review its publishing state and run a [test send](/build/test-and-send).

Previewing content does not establish how every recipient client will display it. Inspect a received test message in the clients relevant to your audience.

### Use the prompt builder

The prompt builder assembles a portable email-design prompt from the selected email type, instructions, design styles, brand colors and attributes. Review the generated prompt before copying it into another tool, especially if your instructions include customer or business information.

Generating or copying a prompt does not publish a template or send an email. Review any resulting design in the template editor and verify its variable references before publishing.

See [Template variables](/build/variables) for data preparation and [Template diagnostics](/troubleshooting/templates) for validation issues.

## WhatsApp template approval

WhatsApp templates have a provider approval lifecycle in addition to Dokaai's saved-content and publication states. Start with a configured WhatsApp channel/provider and a [channel template](/build/templates). Use the existing [Integration guide](/integration) for account-specific requirements.

### Prepare and submit

1. Edit the template's header, body, footer and buttons as needed.
2. Resolve the template's validation errors and provide example attribute values where the approval form requests them.
3. Use **Request Meta Approval**, review the category and approval details, then submit.
4. Check the returned approval/synchronization state. Submitting a request is not the same as receiving approval.
5. Where a synchronization/update action is offered, use it to review the provider state and inspect any reported error.

The dashboard models draft, pending, approved, rejected and stale states. Review the displayed state and provider feedback rather than assuming a guaranteed approval time.

### Edit an approved template carefully

The editor warns that changing a Meta-approved template loses that approval, pauses notifications until approval is completed, and requires publication again after approval. Review the warning before confirming the edit, then follow the approval and publishing steps for the revised template.

Provider approval and Dokaai publication are separate. Once approval and the relevant publication settings are ready, run a controlled [test send](/build/test-and-send) and inspect its [event](/operations/events).

If the state is unexpected, retain the template identifier, displayed state and provider error for investigation. Do not repeatedly resubmit without checking the existing approval request.
